================================================================================
AMAZON ML CHALLENGE 2026: BUSINESS ENTITY RESOLUTION - REQUIREMENTS SUMMARY (V2)
================================================================================

1. PROBLEM OVERVIEW
   - Task: Determine entity resolution (ER) matches across 3 independent, noisy data sources (Source 1, Source 2, Source 3).
   - Reference Source: Source 1 is the deduplicated reference source.
   - Objective: For each entity in Source 1, identify all matching entities in Source 2 and Source 3.
   - Match Cardinality: One-to-Zero, One-to-One, or One-to-Many. A Source 1 entity can match 0, 1, or multiple records across Source 2 and Source 3.

2. CRITICAL AUDIT & CANDIDATE POOL PENALTY RULE (NEW IN V2)
   - Candidate Generation Evaluation: `candidate_pairs.tsv` is audited alongside `matching_results.tsv` for final team rankings.
   - Candidate Pool Efficiency Penalty: Approaches generating a SMALLER, more precise candidate set per Source 1 entity are ranked HIGHER in final evaluation beyond leaderboard score.
   - Candidate Pool Budget: Target an average pool of 5 to 15 candidates per Source 1 entity (hard ceiling 20-25 candidates), replacing broad >100 candidate windows.

3. DATA SPECIFICATIONS & NOISE PATTERNS
   - File Format: Tab-Separated Values (.tsv). Files must be parsed using explicit tab separators (`sep="\t"`).
   - Schema per source file (*_source1.tsv, *_source2.tsv, *_source3.tsv):
     * `entity_id`: Unique identifier starting with prefix `S1-`, `S2-`, or `S3-`.
     * `business_name`: Name of business entity (abbreviations, legal suffixes, typos, transliterations, word-order transpositions, punctuation variations).
     * `business_address`: Address of business (missing components, landmark references, municipal variations, non-standard abbreviations).
     * `country`: String label for country.
   - Ground Truth File (`train_ground_truth.tsv`):
     * Columns: `source1_entity_id`, `matched_entity_ids` (comma-separated list of S2- and/or S3- IDs).

4. OPEN-SET COUNTRY REQUIREMENT (FRANCE IN TEST)
   - Training Set Countries: `US` and `India`.
   - Test Set Countries: `US`, `India`, and `France` (unseen in training data).
   - Mandatory Behavior: Pipelines and models MUST be zero-shot / open-set capable for unseen countries.
     * DO NOT hard-code, one-hot encode, or filter predictions by training countries (`US`, `India`).
     * Avoid country-specific regexes (e.g., US state patterns, Indian PIN formats). Use language-agnostic feature extractors and multilingual embeddings (`BAAI/bge-m3`, `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`).
     * Hard-block by exact country match: candidates(S1_i) must share the same country label as S1_i (slashes candidate search space by 2/3 to 3/4 with zero recall loss).

5. REQUIRED OUTPUT FORMAT & FILES
   - Output Directory: `output/`
   - File 1: `output/matching_results.tsv` (Scored on Leaderboard)
     * Header: `source1_entity_id\tmatched_entity_ids`
     * Final predicted matches for every Source 1 entity in the test set.
   - File 2: `output/candidate_pairs.tsv` (Audited for blocking reduction ratio & candidate efficiency)
     * Header: `source1_entity_id\tcandidate_entity_ids`
     * Exact candidate list passed from blocking to ML classifier.
   - Validation & Constraint Requirement:
     * MUST satisfy: `IDs in matching_results.tsv` ⊆ `IDs in candidate_pairs.tsv`.
     * Submissions MUST pass `utils/validate_submission.py` locally before uploading.

6. EVALUATION METRIC & SINGLETON STRATEGY
   - Primary Metric: Macro-averaged F_0.5 score across all Source 1 test entities.
   - Formula: F_0.5 = (1.25 * Precision * Recall) / (0.25 * Precision + Recall)
   - Precision-Heavy Focus: Precision is weighted 2x higher than recall. Decision threshold θ* skews high (~0.65-0.80).
   - Singleton Safeguard: Singletons score 1.0 if correctly predicted empty, and 0.0 if any false match is predicted. When uncertain, prefer candidate pruning to safeguard singletons.
   - Relative Margin & Source Constraints: Enforce at most one match per source file per S1 entity unless candidates have nearly identical top confidence scores.

7. CONSTRAINTS & COMPLIANCE RULES
   - Strict Prohibition on External Data Lookups: NO commercial ER APIs, government business registries, geocoding services, or internet lookup tools.
   - Model Parameter Limit: Max 8 Billion parameters.
   - License Constraint: Open-source models must follow MIT or Apache 2.0 licenses.
   - Deliverable Package: Single `.zip` containing `output/`, `code/business_entity_resolution/`, and `Documentation_template.md`.
